# XTEINK WebSync v1.3.8

Reliability release from the 2026-10-21 functional audit: device filenames no longer collide across PCs on the same day, applying an update no longer bypasses shutdown, and several shared-folder and settings edge cases are fixed.

## Changes

- Generated EPUB filenames (and EPUB identifiers) now include an 8-character hash of the article set, e.g. `Blog_2026-10-21_1a2b3c4d.epub`. A book built the same day on another PC or output folder no longer replaces an earlier book at the same device path. Existing files on the device are not renamed or removed.
- Applying an update now drains running work before restarting: pending Watch events are preserved, running jobs finish and the shared-folder push is flushed. The update is refused while a sync or preview is running.
- Selected-article sync pushes already-recorded history to the shared folder even when it is cancelled or fails part-way, so other PCs do not resend those articles. A cancelled run still reports `cancelled`.
- Settings recovery (`--recover-config` and the startup dialog) accepts configs that only have semantic warnings, matching what `load_config` accepts; structural errors are still rejected.
- GUI save-conflict merging keeps values owned by background writers (Watch queue, shared-folder timestamps, adopted device IDs, site tombstones) instead of reverting them from a stale in-memory copy.
- Registering the Windows schedule fails early with a clear message when the `schtasks /TR` command would exceed the 261-character limit.
- Removed the unused `upload/romanize.py`; documentation now matches the current Hangul-preserving transfer filenames.

## Verification

- Full local suite: 674 passed, 1 skipped (Windows, Python 3.15). New regression tests fail on the previous code and pass now.
- Isolated frozen build and `--smoke` verified locally before tagging.
- The release workflow performs its own Windows tests, signed manifest build, executable smoke check, and publication.
- Not verified: behavior of a real X3/X4 device when a path is re-uploaded, and Hangul filenames on current firmware (see `docs/AUDIT_VALIDATION.md`).
