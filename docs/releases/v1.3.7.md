# XTEINK WebSync v1.3.7

Auto-update reliability fixes: failed updates are reported once at the next startup, staging leftovers are cleaned automatically, file-lock retries cover replacement and rollback, and staging copies can no longer be launched directly.

## Changes

- Previous update results (`applied`/`failed`) are consumed once at startup: failures show a one-time warning plus a log entry, successes are logged.
- Staging leftovers (`.updates/update-*.exe`) are pruned when a download starts and at startup; declining the apply prompt deletes the staged file immediately.
- Binary replacement and rollback retry transient file locks (Windows WinError 5) for up to ~10 seconds before reporting failure.
- Running an exe from inside `.updates` is blocked with a pointer to the original executable (`--apply-update` helper excluded).
