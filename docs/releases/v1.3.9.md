# XTEINK WebSync v1.3.9

Fixes the in-app updater failing to replace the installed executable (v1.3.8 and earlier stay on the old version).

## Why updates failed

The updater copied the old exe to a backup and then overwrote it. On Windows a running (or still-releasing) executable cannot be overwritten, so the replacement failed with `WinError 5`, the rollback failed for the same reason, and the leftover backup (`x3_websync.exe.v<version>.bak`) made every later attempt fail immediately with "backup already exists".

## Changes

- The update helper now **moves** the installed exe to the backup name and moves the new exe into place. Renaming works while the old process is still running or releasing the file; if the first move fails the installed exe is left untouched.
- A stale backup from an earlier failed attempt no longer blocks retries; an update interrupted between the two moves is recovered from the backup automatically.
- The helper, the relaunched app and the post-update `--smoke` run start with a clean PyInstaller environment so they never reuse the exiting process's temporary files.
- Regression coverage: tests that replace a really running executable (Windows CI), stale-backup/interrupted-swap/rollback cases, helper result reporting, and a pre-release end-to-end check with a real frozen build (`scripts/verify_update_swap.py`).

## Upgrading from v1.3.8 or earlier

Auto-update from those versions still uses the old, broken replacement. Download `xteink-crosspoint-websync-v1.3.9.exe` from this release once and replace the installed exe manually (you can delete a leftover `x3_websync.exe.v*.bak` next to it). Settings, history and output are kept because they live next to the exe. Updates from v1.3.9 onward use the fixed path.

## Verification

- Full local suite passes; new updater tests fail on the previous swap logic and pass now.
- Real frozen build: with the installed app still running and a stale backup present, the helper replaced the executable (`scripts/verify_update_swap.py`); the same check on a build with the previous logic failed with `Update backup already exists`.
- Isolated frozen build and `--smoke` verified locally before tagging; the release workflow repeats its own Windows tests, smoke check and signed manifest publication.
