# 동작 기반 테스트 보강 (2026-10-16)

## 분석 기준

CodeGraph MCP로 `SyncService`, 전체/선택 파이프라인, RSS/CSS 수집기,
HTTP 공통 세션과 기존 통합·복구 테스트의 소스 및 호출 관계를 확인했다.
기존 HTTP/SQLite·다중 PC·프로세스 락·EPUB 계약은 유지하고,
검증이 약한 실행 경로와 단언을 보강했다. 커버리지 수치를 완료 기준으로 쓰지 않는다.

발견한 공백:

- 기존 파이프라인 HTTP 통합 테스트는 수집기 factory를 대체한다. 실제 수집 결과가
  빌더·전송·이력 처리와 연결되는지는 별도 검증이 필요했다.
- 백업 pull/push 실패 통합 테스트는 선택 동기화만 실행하고 전체 동기화는 실행하지 않았다.
- 일부 부분 실패/재시도 테스트는 반환값을 무시하거나 일부 이력만 확인했다.
- 취소·DB 쓰기 실패 테스트는 이후 같은 서비스에서 작업을 정상 재개하는지 확인하지 않았다.
- 공통 HTTP 세션의 크기 제한·리다이렉트·재시도는 주로 응답 mock으로 검증했다.

## 보강한 계약

| 위치 | 실제 실행 및 확인 사항 |
|---|---|
| `tests/test_source_to_device.py` | 실제 RSS XML·CSS 목록/상세 HTTP 수집 → EPUB 생성 → multipart HTTP 전송 → 별도 SQLite connection으로 commit 확인 |
| 같은 파일의 증분 테스트 | 사이트별/합본 모드 각각 검증, 서비스·설정 관리자·DB 객체 재생성 후 새 기사만 전송, 재실행 시 전송 없음 |
| 같은 파일의 미리보기 테스트 | 미리보기/EPUB만 생성은 전송·이력 변경 없음, 선택 기사만 전송, 미리보기 본문 재사용 |
| 같은 파일의 실패 복구 테스트 | 실제 소스 HTTP 404가 다른 소스의 전송을 막지 않음, 실패 결과 반환, 복구 후 실패 소스만 전송 |
| `tests/test_base_scraper_session.py` | 실제 소켓에서 503 재시도·404 비재시도, 상대 리다이렉트, 루프 횟수 제한, 응답 길이 유무별 정확한 크기 경계와 초과 거부, 실패 뒤 세션 재사용 |
| `tests/test_pipeline_failure_recovery.py` | 전체/선택 동기화의 백업 pull/push 실패, 정확한 DB 이력, 락 해제, 취소·저장 실패·공유 폴더 복구 뒤 재실행 |
| `tests/test_pipeline_http_integration.py` | 부분 실패/복구 반환값, 양 기기·전체 기사 이력의 정확한 집합, 세 번째 실행에서 재전송 없음 |

새 EPUB 검사는 ZIP CRC, mimetype, container → OPF → manifest → spine 연결을
직접 따라가 각 XHTML을 XML로 파싱하고 본문을 검사한다. 파일 존재만으로 성공 처리하지 않는다.
RSS/CSS 본문 보존, 광고 제거, 이미지 미수집, `/Books/News` 전송 경로도 확인한다.

새 종단 흐름에서는 수집기·빌더·업로더·DB를 mock하지 않는다.
바탕 화면 알림을 비활성화하고 머신 프록시 영향을 제거한다.
모든 소스와 기기는 임의 포트의 loopback 서버이며 사용자 데이터·실제 기기를 사용하지 않는다.
백업/DB 실패 테스트에서는 실패 지점만 주입하고 나머지 처리는 실제 실행한다.

공통 기기 모의 서버는 응답 뒤 연결을 닫도록 했다. Windows에서 사용이 끝난
HTTP/1.1 연결이 reset되며 발생하던 무관한 서버 스레드 traceback을 방지한다.
요청 처리 예외를 일괄 무시하는 코드는 추가하지 않았다.

## 검증 방법과 한계

```powershell
python -m pytest tests/ -q --tb=short -ra -W error::RuntimeWarning
```

Windows CI의 Python 3.10 작업에도 위 통합·복구·실제 HTTP 세션 테스트를 포함했다.
Linux 전체 테스트 작업은 기존대로 전체 스위트를 실행한다.

로컬 Windows / Python 3.15에서 위 명령은 **632 passed, 1 skipped**로 완료됐다
(115.72초). skip은 POSIX 디렉터리 descriptor 전용 테스트다. 문서 인코딩·테스트의
로컬 경로 의존 검사도 **6 passed**로 완료됐다. Linux 및 Python 3.10 실행 결과는
이 로컬 결과에 포함하지 않는다.

결함 탐지 확인을 위해 pytest 실행 중에만 메모리 패치를 적용했다. 다음 네 가지 결함이
각각 해당 테스트의 실패로 탐지됐다. 제품 소스 파일은 변경하지 않았다.

- `mark_synced_many`를 무동작으로 변경 → 정확한 SQLite 이력 단언 실패.
- CSS 상세 본문에서 제거 선택자를 무시 → 광고 제거 단언 실패.
- HTTP adapter 재시도를 비활성화 → 정상 200 및 본문 단언 실패.
- HTTP 본문 크기 비교를 느슨하게 변경 → 초과 응답의 예외 단언 실패.

이 검증은 실제 CrossPoint 펌웨어나 공개 사이트의 현재 DOM을 보증하지 않는다.
loopback 기기 서버는 HTTP 계약 대역이며, 재시작 검증은 새 서비스/설정/DB 객체를
만드는 방식이다. 별도 프로세스 간 배타 락은 기존 multiprocess 계약 테스트가 담당한다.
